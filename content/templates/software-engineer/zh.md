这个模板适合后端、前端和全栈工程师。它采用单栏布局和朴素的板块标题，招聘系统（ATS）读取它的方式和人读起来是一样的。示例属于一位有九年经验、先后在三家公司工作过的高级后端工程师，但这个结构适用于任何年限。把内容换成你自己的经历，删掉用不到的板块就可以。

## 招聘方看重什么

大多数技术负责人看简历时，主要找三样东西：你做过什么，规模或难度有多大，做完之后带来了什么变化。用过的技术栈当然重要，但它更多是这些工作的背景。

每段工作里，把最近、最有分量的事情放在最前面。你主导过的项目，就写“主导”；你负责过线上值班，就写出来。对服务的负责程度，是判断一个人资历最清楚的信号之一，也是很多人最容易漏写的内容。

很多公司由 HR 或猎头先看简历，再转给技术面试官。HR 会拿你的简历和岗位描述逐字对照，所以语言、框架和平台的名字要写得直接、规范。技术面试官后看，看的是深度：规模、取舍和结果。

## 各板块怎么写

### 个人信息和联系方式

姓名、求职意向、所在城市、手机、邮箱，再加一到两个链接。国内简历一般会写求职意向，例如“后端开发工程师 / 杭州”。GitHub、个人博客或作品链接，只在里面有真实内容时才放。不需要写详细住址，出生年月、民族、政治面貌等信息，除非岗位要求，否则可以省略。

职位名称用你想应聘的方向，前提是真实。比如公司内部职级叫“开发 P6”，对外写“高级软件工程师”更好理解。

### 个人简介

两到三句话：你的年限、主要技术栈、做过什么类型的系统，以及你在意的一件事。用平实的语言写。下面是不同年限的写法示例：

> **初级：** 软件工程师，一年内部工具开发经验，主要使用 Python 和 React。熟悉 SQL、单元测试和代码评审，希望加入做面向用户产品的团队。

> **中级：** 全栈工程师，四年 TypeScript、Node.js 和 React 经验。独立交付过计费和新用户引导功能，擅长把模糊的产品需求拆成可以逐步上线的小版本。

> **高级：** 后端工程师，七年支付和订单系统开发经验，主要使用 Go 和 TypeScript。习惯从方案评审到线上值班完整负责一个服务，重视清晰的接口、稳定的发布和后来人看得懂的代码。

### 工作经历

按时间倒序排列，最近的写在最前面。每段写公司、职位、城市和起止年月。最近的工作写三到五条，较早的写一到三条。如果公司规模小、外人不熟悉，可以加一句说明公司做什么，例如“区域物流软件服务商，约 60 人”。

### 专业技能

把技能分成几行，每行加一个标签，不要写成一长串。示例分为编程语言、后端、基础设施和工程实践四组。每组里把最常用的放在前面。

国内简历常见“精通、熟练、了解”这样的程度描述。用的话要谨慎，“精通”很容易成为面试官重点追问的地方。与其写程度，不如在工作经历里写清楚你用它做了什么。

### 项目经历

如果一个项目能展示工作中体现不出来的能力，或者真的有人在用，就值得写。用一句话说明它做什么、用了什么技术，有数据的话再加上使用情况，比如 Star 数、下载量或用户数。附上代码或线上地址的链接。

### 教育背景

学历、学校、专业、起止时间。工作两年以上之后，教育背景放在工作经历下面，不需要展开写。应届生和工作年限短的同学，可以把教育背景放到最前面，写上相关课程、成绩排名或竞赛经历。

### 证书

技术岗位里比较常见的是云厂商认证（阿里云、AWS、Azure）和 Kubernetes 相关认证，以及软考证书。写全称、颁发机构和年份。在线课程的结业证明，除非岗位明确要求，一般不用写。

## 工作经历怎么写

每一条以动词开头，用平实的话说明做了什么，最后写结果。有数据就写数据：延迟、错误率、发布频率、用户量、成本。没有数据，就具体描述变化，比如“客户看到状态更新的时间从第二天早上缩短到几分钟”。

一个简单好用的句式：**做了什么 + 怎么做的 + 带来了什么变化。**

- 较弱：“参与搜索功能开发。”
- 更好：“基于 Elasticsearch 重做商品搜索，搜索耗时中位数从 1.2 秒降到 200 毫秒，搜索结果点击率随之提升。”

## 技能和关键词

HR 和招聘系统经常按岗位描述里的原词搜索，所以技术名称要用规范写法，比如写“PostgreSQL”而不是“PG”，写“Kubernetes”而不是“k8s”。只写你在工作或真实项目中用过的。

| 类别 | 常见示例 |
| --- | --- |
| 编程语言 | Java、Go、Python、JavaScript、TypeScript、C++、Kotlin、Swift、SQL |
| 前端 | React、Vue、Angular、小程序、HTML、CSS、无障碍 |
| 后端 | Spring Boot、Node.js、Django、REST、GraphQL、gRPC、微服务 |
| 数据 | MySQL、PostgreSQL、MongoDB、Redis、Kafka、Elasticsearch、Spark |
| 云和基础设施 | 阿里云、腾讯云、AWS、Docker、Kubernetes、Terraform |
| 交付 | CI/CD、自动化测试、代码评审、监控告警 |
| 工程能力 | 系统设计、接口设计、故障处理、带新人 |

沟通能力和团队协作对工程师很重要，但简历上一句“沟通能力强”证明不了什么。把它们写进工作经历里：主持方案评审、带新人、写文档、和产品设计协作上线。

## 按岗位调整简历

同一份简历投所有公司，效果不如每次花十分钟针对岗位改一改：

1. 读一遍岗位描述，标出反复出现的语言、工具和职责。
2. 确认其中你真正掌握的，在技能和至少一条工作经历里出现过。
3. 把和这个岗位最相关的经历调到每段工作的最前面。
4. 调整个人简介和求职意向，让第一句话和岗位一致，比如投后端岗就写“后端工程师”。
5. 如果版面不够，删掉和岗位无关的项目。

岗位描述里的说法如果符合你的实际情况，就用同样的词。岗位写“分布式系统”，而你确实做过，就写“分布式系统”，不要只写“微服务”。

## 格式和篇幅

除非有十年以上相关经验，否则控制在一页。全文只用一种字体，正文字号在 10 到 12 磅之间，日期格式保持一致。重要信息不要放在表格、文本框或图片里，有些招聘系统会跳过这些内容。本模板在设计上已经避开了这些问题。

除非对方要求 Word 格式，否则用 PDF 投递。文件名写清楚，例如“陈浩然-软件工程师-简历.pdf”。

## 应届生和转行的写法

应届生的简历，重点放在教育背景、课程项目、实习和竞赛上。实习经历按工作经历的方式写：做了什么、用了什么技术、结果如何。课程设计和毕业设计也可以写成项目，前提是你能在面试中讲清楚自己负责的部分。ACM、蓝桥杯、数学建模这类竞赛有名次的话，放在教育背景下面。

从测试、运维、数据分析等岗位转到开发的同学，可以把以前工作中写过的脚本、工具和自动化流程挑出来，单独写成一条条经历。从完全不同的行业转行，就靠项目说话：选一两个完整的项目，写清楚需求、技术选型和上线后的情况，比列一堆学过的课程更有说服力。

## 板块为什么这样排序

模板把工作经历放在最前面，然后是技能、项目和教育背景。工作一两年以后，你做出来的东西比学历更能说明问题。如果你是应届生，把教育背景和项目往前调，工作经历写短一些。[学生简历模板](/zh/templates/student)就是这样安排的。

证书放在靠后的位置。岗位明确要求时它有帮助，比如云平台方向的团队看重 AWS 或阿里云认证，但单靠证书很少能决定是否进面试。

## 常见错误

- 只写职责不写结果，比如“负责后端服务开发”
- 技能栏堆了三十个名词，看不出哪个真正熟悉
- 写公司内部的项目代号，外人看不懂
- 大段文字。简短的条目更容易快速浏览
- 写只在教程里用过一次的技术
- 不同工作经历里日期格式不统一
- 技术名称拼写错误，比如“Javascript”“Github”，面试官会注意到
- 到处写“精通”，却经不起面试追问

## 投递前检查清单

- 求职意向和个人简介与所投岗位一致
- 最近的每段工作至少有一条写到了结果
- 岗位描述中你具备的技能都出现在简历上
- 链接都能打开，指向的内容你愿意让别人看到
- 日期、拼写和技术名称前后一致
- 文件是 PDF，文件名里有你的姓名
