这个模板适合数据分析师、商业分析师、BI 分析师和运营分析师。它采用双栏版式：工作经历和项目经历放在主栏，工具、证书和语言放在较窄的侧栏，HR 扫一眼就能确认你会不会用岗位要求的工具。示例属于一位在深圳工作、有五年零售电商和本地生活行业经验的高级数据分析师。把内容换成你自己的经历，用不上的板块直接删掉。

| 项目 | 本模板 |

## 招聘方看重什么

招数据分析师的业务负责人或数据团队主管，看简历时最关心两件事。第一，你能不能从混乱的数据里取出正确的数字，而不需要别人逐条检查你的 SQL。第二，你能不能把这些数字讲给不懂表关联、不关心窗口函数的业务同事听，并让他们据此做决定。

第一件事靠技术能力来证明。写清你用过的数据库和工具，经历里要有真实的数据工作：搭模型、修数据链路、把一张谁都不敢碰的宽表整理清楚。第二件事靠判断力和沟通来证明，最直接的写法是说明谁在用你的分析，他们因此做了什么。

主管还会看你有没有“归属感”，也就是某件事是不是你负责到底的。“负责出报表”听起来谁都可以替代；“负责每周经营看板，并解答财务和运营对数据的疑问”听起来就是团队离不开的人。如果某个指标、某张看板或某套报表归你管，就直接写出来。

国内很多简历先经过 HR 或招聘平台的筛选，关键词非常重要。工具名要按招聘信息里的写法来写：SQL、Python、Tableau、Power BI、FineBI、Excel、Hive、ClickHouse。业务负责人后面再看时，会越过工具清单，去看你回答过什么问题、产生了什么影响。

## 各板块怎么写

### 个人信息和联系方式

姓名、求职意向、所在城市、手机和邮箱，再加一到两个链接。国内简历通常附一张正式的证件照，背景干净即可。GitHub、Tableau Public 或个人博客的链接，只有在里面有完成度较高的作品时才值得放。不需要写详细住址，民族、籍贯、婚育状况一般也不必写，除非招聘方明确要求。

数据岗位的职位名称五花八门：数据运营、经营分析、商业分析、BI 工程师，做的事情可能差不多。如果你在公司的正式职位比较特别，求职意向一栏可以写最贴近、也最诚实的名称，比如“数据分析师”，具体经历里再保留公司内部的职称。

### 个人简介

两三句话：你的年限、熟悉的行业、主要工具，以及你擅长回答哪类问题。“认真负责、逻辑清晰、数据敏感”这类词几乎每份数据分析简历都有，写了等于没写。下面是三个层级的写法：

> **应届生：** 统计学专业 2026 届本科生，有一段六个月的电商数据分析实习，独立完成两个 SQL 和 Tableau 项目。能处理杂乱的原始表格，也能把分析结论写成业务同事看得懂的报告。

> **三年左右：** 数据分析师，三年本地生活行业经验，日常使用 SQL、FineBI 和 Python。负责用户运营的看板和专题分析，喜欢追问一个指标为什么突然变化。

> **资深分析师：** 高级数据分析师，五年零售电商和本地生活经验。负责核心经营指标体系，和产品团队一起做 A/B 实验，擅长把业务方模糊的问题拆成可以追踪的指标。

### 工作经历

按时间倒序排列，写公司、职位、城市和起止年月。最近的工作写三到五条，较早的写一到三条。公司知名度不高时，可以加一句背景，比如“华南区域连锁超市，门店约 90 家”。

分析师常常同时支持好几个部门。如果是这样，写一句“支持运营、商品和财务部门”很有帮助，读的人马上知道你习惯面对哪类问题，也能看出你和不同背景的同事打交道的经验。

### 项目经历

对数据分析师来说，项目经历比很多岗位都更重要，因为日常工作的数据和看板大多是保密的。好的项目要能体现完整流程：提出问题、找到数据、清洗整理、分析、给出清楚的结论。每个项目用一两行写清问题、工具和在哪里能看到成果。

公开数据很适合做项目：各城市的政府开放数据平台、国家统计局的公开数据、体育比赛结果，或者你自己长期记录的数据。选一个你真正感兴趣的题目，面试官一定会追问，你是否用心一听就知道。网课里人人都做过的标准练习，除非你加了自己的东西，否则不建议写。

应届生和转行的人，项目经历可以放到工作经历前面，并写得更详细一些：数据量多大、用了什么方法、结论是什么、有没有人看过或用过你的结果。

### 专业技能

把工具分组写，方便快速扫读：数据处理和数据库、分析方法和编程语言、可视化与报表，再加一行工作方式。每组把最熟练的放在第一个。这个版式的侧栏空间有限，正好逼你只写真正会用的。

尽量少写“熟练”“精通”这样的程度词，尤其是“精通 Python”，面试时很容易被追问到答不上来。与其写程度，不如在经历里体现你用它做过什么。

### 教育背景

学历、学校、专业和起止年份。统计学、数学、计算机、经济学、金融学是常见专业，但心理学、生物、新闻、工科背景的分析师也不少。应届生可以写几门相关课程和毕业论文题目，有不错的成绩排名也可以写。工作两三年以后，这部分保持简短即可。

### 证书

数据分析相关的证书主要有两类。一类是国内的分析师认证，比如 CDA 数据分析师；另一类是工具厂商的认证，比如 Tableau、微软 Power BI 的数据分析师认证。写清全称、颁发机构和年份。英语能力可以写在语言栏，例如“英语（CET-6）”。全国计算机等级考试对应届生有一定参考价值，有工作经验后就可以去掉了。

## 工作经历怎么写

好的数据分析经历条目，要写出你分析的问题、用的方法和带来的结果。结果不一定是金额，也可以是某个业务决策、一个提速的流程、一份不再需要反复重做的报表，或者一个在汇报前被你发现的数据错误。

一个简单好用的句式：**分析或搭建了什么 + 怎么做的 + 谁在用、带来了什么变化。**

- 较弱：“负责制作销售看板。”
- 更好：“用 Power BI 搭建区域销售看板，12 位区域经理每周用它制定门店目标。”

数字要写你在面试中能说清来源的：数据量、使用人数、节省的工时、报表数量、实验结果。只知道大概的，就写“约”或者用文字描述变化。分析师比其他岗位更容易被问到“这个数字是怎么算出来的”。

### 按年限举例

**应届生和初级分析师**

- 编写 SQL 每周提取订单数据给运营团队，并与财务口径核对总数
- 用 Excel 和 Python 清洗约八万行会员名单，去重后再交给市场部发送短信
- 把三份手工 Excel 周报迁移到 FineBI，门店经理可以自己按区域筛选
- 为每张报表写清字段口径，新同事遇到基础问题时可以自己查

**三到五年分析师**

- 拆解注册转化漏斗，发现大部分用户流失在手机验证环节，推动产品简化验证步骤
- 用 SQL 和定时任务自动生成月度经营分析报告，每月为团队节省约两个工作日
- 和市场部门一起统一“活跃用户”的定义，并在五张看板上同步口径
- 负责一次定价实验的结果解读，向产品总监汇报结论和需要注意的局限

**资深分析师和团队负责人**

- 负责公司核心收入指标和周会使用的经营看板，财务和管理层每周依据它复盘
- 与产品团队建立 A/B 实验流程，包括样本量估算、分流检查和统一的结果模板
- 带两名初级分析师，在结果交给业务方之前复核他们的 SQL 和结论
- 主导从 Excel 手工报表迁移到数仓分层模型，关键指标有测试、有文档

### 按方向举例

**产品分析**

- 和研发一起制定 App 埋点方案，定义页面浏览、点击和留存等核心指标
- 分析新功能上线后的使用情况，发现多数用户根本没有进入新页面，推动调整入口位置
- 搭建按注册月份划分的留存同期群，产品团队在每月规划会上固定回顾

**用户和营销分析**

- 结合投放花费和订单数据制作渠道报表，发现某个付费渠道主要触达的是老用户
- 用留出对照组评估短信和推送活动的真实效果，而不是只看末次点击
- 用 Python 做用户分层，支撑三次节日大促的人群圈选

**经营分析和财务支持**

- 用 Python 建立每周订单和现金流预测，每周与实际数据对比并修正
- 制作门店排班分析报表，帮助店长把人手安排到客流高峰时段
- 核对仓库系统与财务系统的库存差异，定位到一条数据同步的时间问题

**供应链和门店运营**

- 分析 120 家门店的缺货记录，找出补货周期过长的几个品类
- 搭建门店日报，区域经理每天上午九点前能看到前一天的销售和客流
- 用历史销量做简单的季节性预测，给采购部门备货提供参考

**BI 和报表开发**

- 维护约 30 张 Tableau 看板，下线了半年无人访问的 10 张
- 建立统一认证的数据源和指标口径，各部门不再因为总数对不上而争论
- 把耗时的计算移到数仓中预先处理，让一张常用看板的加载时间明显缩短

## 技能和关键词

HR 和招聘系统会按准确的词搜索。工具名称请按招聘信息里的写法写，只写你在工作或完整项目中真正用过的。

| 类别 | 常见写法 |
| --- | --- |
| 查询和数据库 | SQL、MySQL、Hive、ClickHouse、Spark SQL、Oracle、SQL Server |
| 分析和编程 | Python、pandas、R、统计学、回归分析、A/B 实验、时间序列预测 |
| 可视化和 BI | Tableau、Power BI、FineBI、帆软 FineReport、Quick BI |
| 表格工具 | Excel、数据透视表、VLOOKUP、XLOOKUP、Power Query、WPS 表格 |
| 数据处理 | 数据清洗、ETL、数仓分层、指标体系、埋点设计 |
| 分析方法 | 同期群分析、漏斗分析、用户分层、RFM 模型、归因分析 |
| 协作能力 | 需求沟通、口径对齐、分析报告撰写、结论汇报 |

沟通能力对这个岗位非常重要，但光写“沟通能力强”证明不了什么。把它体现在经历里：给总监做过结果汇报，和两个部门谈妥了指标口径，或者写的文档真的有人在用。

## 按岗位调整简历

同样叫数据分析师，不同公司做的事差别很大。银行和传统企业的分析师可能整周都在用 Excel 和 Oracle，互联网公司的分析师则更多写 Hive SQL、做实验分析。每投一份简历花十分钟调整，效果会好很多：

1. 读招聘信息，标出反复出现的工具、业务方向和工作类型，比如看板搭建、专题分析还是实验分析。
2. 确认你真正掌握的工具，出现在技能栏和至少一条经历里。
3. 把和岗位最相关的经历条目移到每段工作的最前面。
4. 调整个人简介的第一句，比如投用户增长岗位时写“用户增长方向的数据分析师”。
5. 如果有和这个行业接近的项目，把它换到最前面。

招聘信息里的说法如果符合你的实际，就直接用。比如岗位写的是“指标体系搭建”，而你确实做过，就在经历里用这个词，不要只写“做报表”。

## 格式和篇幅

大多数分析师一页就够。字体统一，字号 10 到 12 磅，日期格式和数字格式前后一致，比如全篇都写“80 万”，不要一会儿写“80 万”一会儿写“800,000”。你在报表里会注意到不一致的数字，看简历的人也会。

不要在简历上放图表、技能进度条或者星级评分。招聘系统读不出来，也说明不了真实水平。一条能打开的作品链接比任何进度条都有用。投递时保存为 PDF，文件名写清楚，例如“黄嘉怡-数据分析师-简历.pdf”。在招聘平台上投递时，在线简历和附件简历的内容要保持一致。

## 应届生和转行的写法

校招时，HR 更看重学校、专业、实习和项目。可以把教育背景放到最前面，接着写实习经历和项目经历，工作经历一栏可以没有。实习条目和正式工作一样写：做了什么分析，用了什么工具，结果给谁用了。

从运营、财务、销售等岗位转行做数据分析的人，原来的经历同样有价值。挑出其中和数据有关的部分来写，比如“每周整理全国门店销量并给区域经理出周报”。业务理解是很多纯技术背景的分析师缺少的东西，不要把它藏起来。

## 板块为什么这样排序

工作经历放在最前面，因为你真正回答过的业务问题最有说服力。项目经历紧接其后，因为公司里的看板和报表大多不能公开，项目是让别人看到你实际作品的地方。教育背景放在后面，保持简短。

技能、证书和语言放在侧栏，这样每看一段经历，旁边的工具清单都在视线里，又不占用主栏写成果的空间。如果你投的是网申系统比较严格的大公司，可以参考 [软件工程师模板](/zh/templates/software-engineer) 使用的 ATS 友好单栏版式。还在读书的同学，可以看看 [学生简历模板](/zh/templates/student) 怎样写课程和实习。有财务背景、想转做经营分析的人，[会计简历模板](/zh/templates/accountant) 里也有不少可以借鉴的写法。

## 常见错误

- 只列工具名，不写用它们做了什么
- 写了做过的看板，却不说谁在用、用来做什么决定
- 把公司未公开的数据、客户名称或报表截图放进简历或作品集
- 给 SQL 和 Python 画进度条、打星级
- 作品链接打开是空仓库，或者看板已经失效
- 一份强调“细心”的简历里，数字和日期格式却前后不一致
- 上过一门机器学习网课，就写“精通机器学习”
- 漏写用过的数据库或数仓，而 HR 恰恰经常按这些词搜索

## 投递前检查清单

- 求职意向和个人简介第一句与岗位一致
- 招聘信息里要求、而你确实会的 SQL 和可视化工具都写上了
- 最近的每段工作至少有一条写到使用者、决策或结果
- 作品链接都能打开，加载顺畅，展示的是完成的作品
- 数字、日期和工具名称全篇写法统一
- 文件是 PDF，文件名里有你的姓名和应聘岗位
